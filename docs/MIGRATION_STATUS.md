# NeoForge port audit and repair status

Updated 2026-10-24. This is a maintained, unofficial reconstruction. It builds, but it is **not yet a faithful replacement for the original gun engine**. The first source audit identifies substantial omissions; the tested fixes below do not certify every subsystem. Current verification is **200 GameTests and 96 JUnit tests**. [Owner-authored firing](AUTHORED_FIRING.md), the [input lifecycle](GUN_INPUT_LIFECYCLE.md) and [independent input actions](GUN_INPUT_CONTINUATION.md) supersede the older autonomous-server/main-hand descriptions for predicted firing; current gun protocol is **9.0**.

## Sight FOV reference decisions

Pinned `AimDownSightAction.GetFloat` resolves `fov_factor` from zero-base accumulation, ignoring the conflicting raw action field. `ClientRenderHooks.OnComputeFOV` averages every active ADS/Scope action across the local shooter's gun contexts, then divides the incoming player modifier. The original explicitly reads the local player even when the event belongs to another camera player; that quirk is kept. The port now uses NeoForge `ComputeFovModifierEvent`. Minecraft's own half-step tick smoothing and clamp apply to configured world FOV; the separate hand projection remains untouched. No remembered factor or ADS pose blend participates in this calculation.

`ads_zoom` remains an optional strength adaptation: fresh configurations default to authored strength1; an existing saved0.5 stays0.5. Zero strength preserves the incoming modifier. Factors below1 remain valid. Deviation: nonpositive/nonfinite aggregate divisors and nonfinite results leave the incoming modifier unchanged, rather than propagating invalid projection values. Very small positive factors are preserved; later Minecraft clamping is not duplicated in the helper.

Evidence: unchanged production at the preceding mode commit failed six of seven development-client checks, including Krag5 versus4, iron2.25 versus1.25, maximum versus per-action mean, weak factors, offhand contribution and hand projection. Four source-derived unit methods now cover arithmetic, action weighting, incoming modifiers, strength and invalid/tiny factors. The full111 GameTests and36 unit tests pass. The first fixed client with saved strength0.5 passed seven checks and observed world28/62.222 degrees for Krag scope/iron, with hand70. The exact final production version with newly generated strength1 passed ten checks, adding a synthetic remote event owner, offhand-only and released-state checks; actual world projections settled at17.5/56 while hand stayed70. The custom0.5 run preceded only the local-owner and tiny-factor review repairs. Commands use transient client inventory copies for event contracts and restore original references; they do not establish legitimate simultaneous input with two two-handed guns or a natural spectator transition.

These are FOV foundations, not full aiming parity. The subsequent repair below replaces toggle/base-first lookup with retained provider metadata. General concurrency and unsupported actions, richer shooter/active-ability inputs, attachment eye points and mounted geometry, pose/scale transitions, overlay/crosshair rules and gun visibility remain open. No live original, dedicated observer, latency or new performance-profile claim follows from these checks. Recovery baselines and credits are unchanged.

## ADS pose reference decisions

Pinned Flans `FirstPersonManager.RenderTick/CalculateADSPosition`, `FlanItemModelRenderer`, `BakedTurboRig` and `Transform` define the pose. Active ADS/Scope actions now come from retained provider metadata. `eye_line_name` uses available modifiers; group names do not imply eye-point names. Both logical hands follow the preferred physical arm. FOV remains a separate per-action calculation.

- **Quirks kept:** the HashMap key is physical hand plus full group path, without gun/owner/activation identity. The first entry captures eye name/type/index; reusing a surviving key retains that selection and blend. Multiple sight actions in one group contribute one pose. Active/inactive frame rates are 8/10, with a clamped fraction and no extra 0.1-second time cap. Removal is strictly below 0.01. Without a local player the map freezes rather than clearing.
- Same-hand positions use normalized weighted means; orientations use ordered cumulative JOML shortest-arc slerp in HashMap traversal order. A separately clamped total controls interpolation from the hip transform. Any retained other-hand entry halves that blend and prepends physical left/right roll, including eye-position cancellation. Uniform hip `scale.x` interpolates toward 1: Gyrojet 0.6875 reaches 1, with 0.84375 halfway.
- Eye points use the currently **rendered** stack and static rig, including the old stack retained during re-equip. Stack-bound overrides prevent mixing an old rig with new inventory attachments. Alignment excludes active animation: the original uncached `GunContextItem` uses the empty Invalid action stack even though its AP helper receives `animated=true`. Mount and child transforms compose recursively with pixel offsets divided by 16. Slot zero prefers an existing unnumbered mount; higher slots are numbered. Failed steps contribute identity while retaining valid mount/child transforms and instance weights.
- **Safety deviation:** multiple zero/nonfinite-total weights return identity instead of the original zero-division transform. Float JOML matrices replace mixed double-position/float-orientation transforms; numeric tests use tolerances. No authored model values were changed to hide an optic lens.
- Two of three scale oracles fail against unchanged pre-repair production. The native G11+telescope baseline uses bare eye `(0,0.515625,0.234375)` instead of mounted `(0,0.53125,0.03125)`. Repaired native checks cover both preferred arms, removed-child mount retention, bare G11, both Krag overrides, Krag's plain slot-zero mount and Gyrojet scale. Pure tests distinguish path reuse/recapture, duplicate actions, exit boundaries, weighted/noncommuting quaternion poses, cross-hand roll/translation, mount priority and partial failures. Controlled real item-renderer checks retain an old model while selected inventory becomes empty or changes attachments; naturally timed re-equip remains unverified.
- The first expanded Krag sequence was invalid: its authored default is `off`, so the first switch selects `0`, not `1`. Its no-group/wrong-eye results remain excluded from green claims; corrected sequences explicitly cycle `off -> 0 -> 1`. Review caught and repaired a held-icon delegation bypass introduced with stack-bound models. Native override checks compare the returned icon model and transform for telescope/red-dot attachments in both hands. An initial fixture incorrectly expected the ordinary generated rifle-ammunition model to be a TurboRig icon; that failed precondition is retained separately.

Overlay opacity/camera gating, any-ADS crosshair suppression, local-gun visibility timing, mounted meshes, skins, animation/camera feedback, richer shooter/ability inputs and full action concurrency remain open. The legacy global blend accessor now returns the maximum full per-hand transition for existing overlay/trail consumers; it does not certify those paths. Dedicated observers, latency, original-client visual comparison and representative render profiling remain unverified.

## Scope presentation and visibility reference decisions

Pinned `ClientRenderHooks`, `AimDownSightAction`, `ScopeAction`, `ClientActionManager`, `FlanItemModelRenderer`, `GunItemRenderer` and `FlashEffectRenderer` define separate presentation paths. The first Scope in main/offhand, group activation and authored action order draws immediately at full opacity, centered at width four times screen height. Camera type and pose blend do not gate it. Every active ADS/Scope suppresses the crosshair even without an overlay, including under the existing VANILLA crosshair option; explicit user hide options retain their behavior.

- **Quirks kept:** each Scope action starts magnitude zero and advances by `m += (1-m)*0.05` on eligible **client** action ticks. Values 0.05/0.0975/0.142625 hide the gun from the third tick. Clocks belong to the retained action instance, so retriggers preserve magnitude and a new activation resets it. Inventory guns continue ticking while unequipped. This lifecycle is independent of physical-hand/path pose blending.
- Nonzero raw delays queue an integer countdown after truncation, including fractional/negative values. Pending actions skip the due tick as well; a delay of 2.9 hides on tick five, 0.9 or a negative delay on tick four. Retrigger overwrites pending delay without resetting magnitude. Individual Scope actions have separate slots; any matured Scope can hide, even if another Scope supplies the selected overlay. All 54 bundled ADS/Scope actions omit delay, but synthetic clocks test these original rules too.
- **Protocol adaptation:** runtime descriptors now carry a delayed-Scope trigger revision. Only groups containing a nonzero-delay Scope update it on retrigger; ordinary firing/zero-delay sight descriptors retain their prior identity and unchanged-tick behavior. Actual ItemStack streaming retains the revision and activation together. Mandatory gun protocol is **4.0**. Client clocks count eligible local ticks, not server `startedAt`; notification arrival phase and delayed/multiple delivery cannot reproduce all original predicted-client timing. Dedicated latency/TPS divergence and mixed-version handshake remain unverified.
- **Rendering context correction:** ordinary original BEWLR explicitly supplies LocalPlayer only for first-person rendering. It supplies no entity for ordinary third-person/ground/fixed/head, and GUI uses its icon path. An earlier broad inference from `GunItemRenderer` alone was incorrect: ordinary third-person gun meshes stay visible. In first person, mesh validity and Scope visibility use the **current logical-hand** gun context, while ADS alignment separately uses the actual retained render stack. An old gun mesh is skipped if that current hand becomes empty/nongun; a valid unscoped replacement permits the old mesh during re-equip. The port now culls gun quads at this point, without cancelling the other hand or the whole RenderHand event.
- Original flashes render independently of `ScopeAction.ShouldRender`. Review caught an initial cull that also removed baked flash quads; the repaired path returns eligible flash-only quads for a scoped gun, while invalid current-hand context emits none. Existing global/main-hand flash provenance, timing and broader effects remain separate open work.

Final verification passes 129 GameTests / 62 unit tests. The unchanged export runs 129 tests with one delayed-scope metadata failure; its client has 15 failed presentation/model checks and three failed clock samples. The final client passes 33 scope checks, ten first-five-tick samples over two activations/preferred arms, 13 existing sight/render/icon checks and ten FOV checks. Settings are restored byte-for-byte and both final/baseline clients exit successfully without logged errors.

The unchanged-production GUI/model baseline exposes immediate overlay, opacity/geometry, third-person overlay, plain/offhand crosshair, opposite-hand cancellation and missing mesh suppression defects. ## Mode and sight lifecycle reference decisions

Pinned `ModeDefinition`, `FlanItem`, `GunContext` and `SwitchModeAction` define the contract. A mode defaults to key `mode`, values `on/off` and default value `off`; the default is independent of the cycle array. Fresh Krag/Lebel `iron_sight` is therefore `off`, with neither sight enabled. The first switch selects `0`, the second `1`, then `0`. Bare modal checks require `on`; multiple colon fields use only fields zero/one; `!key` remains a literal key, not negation. Server resolution and HUD use the same mode-value helper.

`GunActionState.modesInitialized` preserves the original distinction between no mode compound and an existing compound with a missing key. Only the former uses a definition default; the latter reads an empty string. Legacy nonempty maps infer initialized presence; absent/empty legacy maps retain their old absent state. Explicit initialized-empty state survives every state helper, item save and actual ItemStack packet codecs. This added a boolean at protocol `2.0`; current registration is protocol `3.0` because of the later runtime provider component, requiring a matching build. Same-build codec and integrated-client paths are tested; a mixed-version handshake rejection has not been exercised. Original 1.20 raw NBT migration is not claimed.

SwitchMode resolves mode/set_value through the available group then gun/attachment modifier sources, preserving the original gun-over-group priority. Nonempty `set_value` selects its literal even outside cycle values; a cycle uses the last matching index, with an absent value selecting entry zero. **Quirks kept:** cancellation scans root handler modal strings with `startsWith(modeKey)`; a deferred attachment overwrites its path for each child, so only the last child is marked finished. An absent/invalid attachment or empty child handler retains the root path. Active source lookup compares resolved plain `Def.key`, aliasing base and attachment groups with equal keys; separate namespace identities must not be invented as a supposed parity fix. The later retained-context repair above preserves that first-created context and action list; general concurrency remains open.

Cancellation marks runtime frames finishing and retains their due final callback tick. Toggle state is removed after that tick; work still pending after removal is discarded. Self-cancelling firing callbacks retain a valid cycle during emission/synchronization, then finish normally. The existing server-authority adaptation suppresses future authoritative retriggers rather than promoting an uncertain final client-only prediction into extra damage. Same-world ordering between concurrent groups and original live network propagation remain unverified. Generic reload cancellation still goes through the reload boundary path. Saved/copied/logout/dead sight toggles without a current runtime owner are cleared while selected mode values survive.

Direct mode-state writes do not run the SwitchModeAction cancellation scan. `autoCancelIfNotInMode` has no active reads in the pinned engine and remains inert. Empty cycle arrays and malformed trailing-colon checks are refused rather than reproducing source index crashes. The original setter also dispatches a SwitchMode ability trigger with base/self context; the pinned pack has no such authored triggers, and that hook remains on the general triggered-ability queue. Shooter and active-ability string overrides and competing attachment-order behavior are not certified by this unit.

Sixteen new server scenarios distinguish defaults, modal rules, missing compound/key behavior, literal/duplicate/attachment priority, final callbacks, prefix/last-child/plain-key aliases, root fallback, self-cancelling full-auto and stale sight ownership. Fifteen fail against byte-identical `590546d` production; the direct-write/inert-field control passes there. Four unit baseline failures cover mode schema defaults and stored presence. Final verification passes **111 GameTests and 32 unit tests**. Focused read-only source review caught and closed a root-fallback omission and a scheduler reentrancy/nulling defect; these are included in the final tests. The self-cancel runtime case covers initial held FullAuto; repeated/multi-emission reentrancy is source-reviewed rather than separately exercised.

An actual integrated client drove Use input and the existing SpecialKey2 poll for Krag and Lebel, received matching server mode/toggle state, and captured scoped/iron views. Both start `off`, remain unaimed on Use, then select `0/ads_0`, switch to `1` with the old toggle cleared, enable `ads_1`, and switch back to `0` with no active sight. Four inspected screenshots show separate scope overlays and iron-sight views. No dedicated observer/latency, live original comparison, complete arm/rig transform equivalence or full pack playthrough is claimed. The entire migration matrix remains active.

## Firing cadence reference decisions

- Compared pinned Flans `ActionManager.KeyPressed/KeyHeld/KeyReleased`, `ActionGroupInstance.DoInitialTrigger/CheckRetrigger/UpdateInputHeld/Finished`, `ActionStack.TryShootMultiple/OnTick` and `ShootAction.CanRetrigger`, including the owning-player network path. The only authored BurstFire group is G11 `primary_fire`: repeatCount 3, repeatDelay 0.055 seconds, with a 0.75-second animation.
- Original fractional cooldown is decremented/clamped per tick, and each positive-delay trigger adds delay * 20 until cooldown reaches at least 1. The G11 therefore triggers on ticks 0/1/2; MAT-49's 0.1-second interval triggers on ticks 0/2/4. Fractional remainder is retained between presses rather than rounded away. Unit tests also cover sub-tick multi-trigger rates and zero-delay initial actions.
- **Quirks kept:** BurstFire decrements its remaining retrigger checks once per tick, including failed/no-ammo checks; release does not cancel it. A positive-delay burst gets repeatCount - 1 checks after its initial trigger; zero-delay initial triggering does not schedule them. Group duration is floor(max(repeatDelay, authored action durations) * 20), and SemiAuto/BurstFire end when progress exceeds duration * trigger count. Retriggering an existing group retains progress and increases its trigger count. Declared animation lifetime is not an extra cooldown that prevents a fresh burst press.
- **Protocol adaptation:** the original owning client schedules triggers and forwards them. This port now schedules repeats on the server from input edges. Duplicate/legacy held packets do not create new semi-auto/burst presses. Full auto keeps firing without per-shot client requests and stops on release, including a release arriving after selecting an empty hand. Normal 20 TPS cadence is source-derived and tested; latency/divergent client/server TPS remains unverified.
- Action stacks continue ticking for inventory guns after a hotbar switch, as in `ServerActionManager.ServerTick`. Runtime controls are held outside saved item components, discarded on logout/server stop, and pruned when inventory ticking ceases. Reload interrupts retriggers; dropped/reloaded stale firing metadata cannot resume a phantom burst. Dead/spectator owners are prevented from continuing scheduled fire.
- Client animation/flash confirmation observes the growing group trigger duration, so repeated server shots restart their effect instead of requiring another local press. The deterministic animation-state test verifies this restart; full model/FX parity remains on the rendering queue.
- Safety deviation for malformed content: cap generated triggers at 64 per tick and clamp extreme sub-tick intervals to that bound. No authored interval approaches this limit. The runtime caches resolved group/attachment data during a firing cycle and publishes one immutable firing-frame state per tick; this is not a broad performance certification.

## Action timing and reload reference decisions

- Pinned Flans `ActionGroupInstance`/`ActionStack` are the timing reference. `ActionDefinition.delay` is a float measured in **ticks**. Exactly zero executes immediately; every nonzero value queues a Java-int-truncated countdown. Thus 0.4 and -0.4 execute on the next eligible tick, while 2.9 executes after two ticks. The codec now retains the float until dispatch rather than truncating it during decoding.
- Pending slots are indexed by action identity within a runtime group. A retrigger overwrites that action's countdown; it does not append an independent event. Two identical JSON action entries retain separate slots. Due callbacks run before the next retrigger. Different simultaneously due callbacks use deterministic authored index order; original HashMap iteration did not promise an order.
- Duration is `floor(max(repeatDelay, action durations) * 20)`, excluding delay offsets. SemiAuto/BurstFire ends at progress **greater than** duration times trigger count. A zero-duration group still ticks once; later callbacks are discarded when the group ends. The gun's runtime timeline and generic state claim a gameTime once, preventing same-trigger-time or duplicate inventory calls from advancing phase clocks independently of pending work.
- Runtime ownership is scoped to player, ItemStack identity and group key, including groups without delayed callbacks. Saved/copied/transferred stages have no live owner and are cancelled. An inventory tick gap, logout or owner death cannot resume an old reload and consume the current holder's ammunition. Merely selecting another slot keeps valid inventory actions running. Groups with no delayed actions share empty pending arrays; pending state is not serialized.
- **Protocol/safety adaptation retained:** release can execute already-due feedback on the group's final tick, while it prevents an extra authoritative shot. The original owning client can predict a final FullAuto retrigger before removing the group; inspection did not establish propagation of that trigger to the server. It is not reproduced as additional server damage. Releasing with an empty selected hand also clears the old gun's held trigger, preventing the original phantom-fire risk.
- Reload transitions now consult current capacity/ammunition at each boundary, rather than a fixed initial queue. Entering LoadOne first dispatches its initial actions, then transfers ammunition. FullMag fills free slots at that entry, not at End. Reentering the same LoadOne retains progress and increases duration times trigger count: for duration 11, initial progress 0 is followed by trigger progress 12, 23, 34 and 45. Remote LoadOne animation time is normalized to that latest trigger; other repeat modes do not use this inference.
- Source-derived 1887 timeline with five rounds: Eject at 23; rounds load at **46/58/69/80/91**; End at 102; completion at 116. G11: Eject 21; all available magazine ammunition loads at **42**; End 53; completion 74. GameTests check every intervening tick, including final boundaries and ammunition added mid-reload. Integrated-client normal reload key polling/network followed those same timelines, with matching server/client counts. The client's remote-pose resolver returned phase zero for every repeated 1887 load, but no dedicated remote player was used.
- All 71 authored nonzero offsets are sounds, casings or particles. The native client submitted both WZ38 magazine sounds after LoadOne, preserving their separate 10/40 offsets in server tests; backend client timestamps differed by 29 client ticks, which are not the server clock. A Krag shot submitted its delayed mechanical sound at the expected server offset 20. Exact first-person/observer visual alignment, native casing flight/pickup behavior and authored particle parameters/attachment points remain in the rendering/effects queue; delayed dispatch does not certify those implementations. No screenshot or human listening comparison to the original is claimed.
- A fresh export of pre-repair `afff52a` with only test fixtures added fails **15 runtime cases**; original float-delay decoding also fails a unit oracle. Current validation is **81 GameTests / 28 unit tests**. The initial casing fixture chose a Chassepot magazine that explicitly disables ejection; the corrected baseline uses Vetterli-Vitali. A longer-lived audio observer initially hit NeoForge time-sync channel negotiation without a real connection; its test-only channel response was corrected and sound packets are filtered by identity/origin. That crashed run produced no fresh test report and is not used as evidence of a product regression.
- Pending verification: manual reload cancellation and action restrictions; unbundled repeat/ability actions, live resource reload, magazine conversion, original-engine live runs, standalone server/reconnect/latency and representative performance. These tests do not close the full gun or port parity matrix.
